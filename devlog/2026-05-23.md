## 修复：LLM 指令无法驱动 AI 动作

### 根因
main.js 的 loadLevel() 方法中有一行 	his.aiPlayer.update = function () {};，
覆盖了 iPlayer.js 中定义的真实 update() 方法。导致：
- ✅ llmClient.sendCommand() 正确调用 iPlayer.setExternalCommand()
- ✅ 外部指令被正确存储
- ❌ 但 update() 是空函数，永远不会处理指令

### 修复
- 移除了 main.js 中覆盖 iPlayer.update 的占位代码
- AI 队友的 update() 现在来自 iPlayer.js，包含完整的外部指令处理逻辑
- 添加了 console.log 调试日志，可通过 F12 控制台追踪

## 修复：AI 出生掉进裂缝死循环

### 根因
AI 默认启用自主寻路模式，出生后自动朝终点移动。
关卡 1 的地面中间有断裂（致命裂缝），AI 走到断口处掉进去 → 死亡重生 → 再次寻路 → 再次掉进去 → 死循环。

### 修复
- AI 改为**等待模式**：没收到语音指令时原地静止（只处理重力/碰撞让自己站稳）
- 彻底移除了自主寻路代码（朝终点自动移动 + 自动跳跃 + 卡住检测）
- 只有通过语音 → LLM 收到外部指令时 AI 才会动
- 指令超时（15秒）后自动停，等待下一条指令

### 当前行为
| 状态 | AI 行为 |
|------|---------|
| 未收到语音指令 | 原地站立（橙色方块，显示 AI 标识） |
| 收到语音→LLM 指令 | 执行指令动作（显示 VO 标识） |
| 指令超时（15秒） | 停止，回到等待模式 |

### 修复：音量参数未作用到移动速度和跳跃初速度

**问题**：_setVolumeScaledDistance() 只设置了 _moveDistanceRemaining（STP），没有设置 moveSpeed（SPD）和 _tempJumpVelocity（JV），导致无论音量大小，SPD 和 JV 都不变化。

**修改**：
1. js/aiPlayer.js — _setVolumeScaledDistance()：新增 moveSpeed 和 _tempJumpVelocity 根据音量 actor 缩放（SPD: 80~350, JV: -200~-1200）
2. js/aiPlayer.js — setExternalCommand()：新增 	his._tempJumpVelocity = null，防止旧指令的跳跃速度污染新指令

### 三项调整：缩小参数 + 线性映射 + 防连跳

1. **缩小基础值**：moveStepDistance: 280→200，jumpVelocity: -380→-300
2. **线性连续映射**：移除 moveSpeed 和 _tempJumpVelocity 的 Math.min/Math.max 钳制，输出严格遵循 actor = 0.3 + vol×1.7 线性公式
3. **防连跳机制**：新增 _hasJumpedForCommand 标志位，每个指令最多执行一次跳跃，落地后不再重复跳

### 修复语音指令无响应（看门狗 + 出错回退）

**问题**：语音识别有时会静默失效（浏览器节流/状态污染），或 LLM 出错时 AI 无任何反应。

**修改**：
1. js/voice.js — 新增看门狗机制：每 5 秒检查一次是否有 onresult 事件，超过 15 秒无结果则强制重建识别器
2. js/voice.js — 两个 onresult 处理器均更新 _lastResultTime 时间戳
3. js/voice.js — stop() 中清理看门狗定时器
4. js/llmClient.js — HTTP 错误、解析失败、网络异常三个路径均调用 setExternalCommand('stop')，确保 AI 出错时至少停止

**问题**：	estConnection() 返回 alse 时 UI 只显示"检查 API Key / 端点 / 模型"，无法定位真实错误（如 HTTP 401、模型不存在等）

**修改**：
